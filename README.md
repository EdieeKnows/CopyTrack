# CopyTrack 复印任务叫号系统设计方案

## 背景与设计假设

企业文印室需要一个简化的复印排队叫号系统，用于管理经过审批的复印任务。本方案基于给定的业务流程，从零开始设计系统架构和功能模块，以满足以下需求和假设：

* **内网独立部署**：系统部署在与互联网隔离的内网环境中，保证数据安全。
* **硬件设备**：结合标签打印机和条码扫描器。
* **任务范围**：仅包含复印任务，不涉及扫描、打印。
* **用户与操作员**：多用户并发，一名操作员串行处理。
* **功能目标**：从审批数据同步、自助取号、实时状态跟踪到加急管理和统计导出。

## 系统架构概述

系统采用分层模块化架构，包括：

* **OA审批系统**：提供复印申请审批流程，数据同步至复印叫号系统。
* **复印叫号系统服务器**：管理任务状态、接口通信、任务调度、打印控制。
* **任务数据库**：存储任务单、用户信息、状态变更记录。
* **用户终端**：自助取号设备，支持刷卡登录、任务选择、加急申请。
* **用户Web界面**：内网访问，查看进度、申请加急。
* **操作员终端**：管理任务队列，扫描任务条码标记状态。
* **标签打印机 & 条码扫描器**：用于任务条码标签打印和识别。

## 工作流程与数据流

1. 用户在OA系统申请复印并通过审批。
2. 系统定时同步任务至复印叫号系统。
3. 用户到文印室刷卡取号，选择任务打印条码标签。
4. 用户将标签贴于原件并交给操作员。
5. 操作员扫描条码，开始复印。
6. 复印完成再次扫描，标记完成状态。
7. 用户通过Web查看状态并前往领取，交接后再次扫描完成任务归档。
8. 用户可在取号或处理中提出加急请求，操作员审核。
9. 系统可导出任务处理与加急统计。

## 模块划分与职责

### 1. OA集成模块

* 定时轮询或推送机制获取已审批任务。
* 任务记录写入数据库并生成唯一任务单号。

### 2. 用户取号终端模块

* 刷卡登录
* 显示个人待处理任务
* 任务选择+标签打印
* 加急申请界面

### 3. 用户Web查询模块

* 登录后查看任务进度、状态
* 加急申请入口
* 通知/推送（支持企业微信或OA消息中心）

### 4. 操作员终端模块

* 接收扫码任务，标记处理中/完成
* 加急队列管理与审核
* 手动输入任务编号备用

### 5. 标签打印模块

* 支持ZPL等打印协议
* 生成任务条形码（Code128）及摘要信息
* 打印状态反馈与异常处理（如缺纸）

### 6. 队列与状态管理模块

* 状态流转（待取号 → 排队中 → 处理中 → 完成 → 已交付）
* 支持加急优先机制与队列动态调整
* 防重复取号、幂等扫描处理

### 7. 报表统计模块

* 查询与过滤（状态、加急、时间段）
* 数据导出Excel/CSV
* 管理用统计图表（任务量、等待时间、加急率）

## 数据表设计示意

### 表名：`tasks`

| 字段           | 类型       | 描述     |
| ------------ | -------- | ------ |
| id           | INT      | 主键     |
| task_code    | VARCHAR  | 唯一任务单号 |
| user_id      | VARCHAR  | 用户工号   |
| user_name    | VARCHAR  | 姓名     |
| copies       | INT      | 复印份数   |
| status       | ENUM     | 状态     |
| urgent       | BOOLEAN  | 是否加急   |
| created_at   | DATETIME | 创建时间   |
| printed_at   | DATETIME | 标签打印时间 |
| start_time   | DATETIME | 开始时间   |
| finish_time  | DATETIME | 完成时间   |
| delivered_at | DATETIME | 交付时间   |

## 条码与打印机建议

* **条码类型**：Code 128
* **内容**：任务单号
* **打印机推荐**：Zebra GK420d，兼容ZPL协议

## 扩展能力

* 多操作员并发处理：任务可按操作员分组队列
* 内网微信小程序支持移动查看状态
* 企业统一登录认证 + 消息推送（企业微信）

## 总结

本设计为企业内网环境下的复印任务管理系统，使用扫码与标签机制实现任务追踪、排队与归档。系统结构清晰，模块职责分明，支持扩展及统计功能，可有效提升文印室任务透明度与服务效率。

## 项目实现概述

本仓库基于 Django 框架实现 CopyTrack 复印任务叫号系统，包含以下子模块：

- **OA 集成模块**：`copytrack/tasks/services/oa_integration.py` 提供 CSV 导入与数据同步逻辑，对应管理命令 `import_oa_tasks`。
- **用户自助终端模块**：`templates/tasks/kiosk_*.html` 与 `KioskTasksView` 支撑刷卡取号、打印标签与加急申请。
- **用户 Web 查询模块**：`WebTaskListView` 提供查询入口，展示任务进度和最新事件。
- **操作员终端模块**：`OperatorConsoleView` 与 `ScanForm` 用于扫码变更任务状态，并记录事件。
- **标签打印模块**：`LabelPrinter` 构造 ZPL 指令并触发打印，同时更新任务状态。
- **队列与状态管理模块**：`queue.py` 提供队列查询，`Task` 模型封装状态流转方法与事件记录。
- **报表统计模块**：`ReportView` 支持筛选、统计与 CSV 导出，`statistics.py` 负责数据聚合。

### 快速开始

```bash
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

- 自助终端：`/kiosk/login/`
- 用户查询：`/web/tasks/`
- 操作员控制台：`/operator/`
- 报表统计：`/reports/`

如需同步 OA 数据，可执行：

```bash
python manage.py import_oa_tasks oa_export.csv
```
